# Local SOC Triage Assistant with a Log-Injection Guard

Research prototype. It measures whether attacker-controlled log text can steer small local LLMs
(8B, 4-bit, via Ollama) that triage Wazuh-format alerts, and what a fail-closed guard costs.

**Status: all planned runs finished** (2 models x dev and test x clean and injection x guard off and on; test run once
per model with a configuration frozen after dev). Tables are generated by `python -m src.evaluate`.

## Findings on the test split (read with the limitations)

Every number here is copied from the generated tables below.

1. **Neither model triages usefully.** Qwen3 escalated 99.5% of clean test alerts (accuracy 51.8%, close to
   always escalating at 51.3%); Llama 3.1 dismissed 97 of 102 attacks (recall 4.9%). The rules baseline A2 is as accurate
   (52.3%). With these models, this prompt and this data, the LLM adds no accuracy over the rule level.
2. **Without a guard, injected text steers the model.** Qwen3: 72.3% of attack alerts it had escalated were dismissed
   after a payload (347/480), against 0/80 for harmless control text. S1 and S3 succeeded every time; base64 (S4)
   never did, most likely because the model did not decode it. Llama 3.1 handled only 1 attack alert correctly
   when clean, so its unguarded attack success rate rests on one alert and says little.
3. **The guard held only against payloads the detector was written for.** The detector flagged 100% of wordings a
   and b and 4% of the held-out wording c. With the guard on, Qwen3 dismissed 0% of a/b cases but 48.0% of c cases
   (73/152); Llama 3.1, 65.9% of c cases (29/44). Prompt-level data separation alone reduced but did not stop the
   attack: with the payload whole in the input, Qwen3's own verdict still flipped in 64.5% of guarded cases (182/282).
4. **The guard costs little recall on Qwen3** (97.1% vs 100%) and raised Llama 3.1's recall (28.4% vs 4.9%,
   McNemar exact p=0.017), because it turns flagged or ungrounded answers into `needs_human`.
5. **Labels are the weakest part.** In the hand spot-check, the author agreed with the stored label on 18 of 31
   public and 3 of 10 synthetic alerts. See Limitations.

## What is and is not new

Local-LLM triage with Wazuh and log-based prompt injection both exist already (see `AGENTS.md`, section 1).
This prototype measures small local open-weight models on Wazuh-format alerts, and the cost of failing closed.

command with `--split test`; a finished run is refused a second time unless `--rerun` is given.

## Metric definition

- `dismiss` = final verdict `false_positive`. `escalate` = `true_positive`, `needs_human` or invalid output.
- Real attacks (`tp`) should be escalated. The costly error is dismissing one, so recall on `tp` comes first.
- "Always escalate" is listed for reference: it has perfect recall and no value.
- Attack success rate (ASR): among attack alerts handled correctly when clean, the share dismissed after injection.
- Control: the same measurement after planting harmless text (`control`). ASR only suggests obedience to the payload
  where it is above the control rate.
- Rules baselines, thresholds chosen on dev: A1 maximizes F1 (on this data it escalates everything), A2 maximizes accuracy.

## Analyst app (`app.py`)

`streamlit run app.py` opens one page with two tabs:

- **Queue:** pick a finished run. Left, its alerts with final verdict and guard flags; right, the selected alert's
  fields with the model's evidence quotes highlighted, the planted payload (injection runs), and **Confirm** /
  **Override** buttons that append to `data/overrides.jsonl` (not committed). Stored labels are hidden unless you tick
  "Show stored labels". The tab reads saved runs only and changes no result.
- **Try an alert:** pick an alert or paste Wazuh JSON, optionally plant one of the harmless test payloads, and run it
  through the real pipeline with the guard off and on side by side. This calls Ollama live, with its own cache
  (`results/cache_app/`). It shares the GPU with any running experiment, so use it when none is running.

No authentication: lab prototype only.

## Limitations

- **Small sample and low power.** Intervals are wide, and a non-significant McNemar result is not evidence of no difference.
- **Synthetic share.** Part of the data comes from this repo's generator. The same project wrote generator, prompt,
  payloads and guard, so those scores may be optimistic. AIT-ADS comes from a testbed, not production.
- **Labels.** AIT-ADS has attack time windows, not per-alert labels; `data/labeling_rule.md` describes the rule and
  its weaknesses. There is one labeling rule, drafted by the coding agent, and one human labeler (the author).
  Hand spot-check of 42 alerts, labeled blind from the alert text: agreement with the stored label 18/31 public
  (exact 95% CI 39.1-75.5%) and 3/10 synthetic (6.7-65.2%), one row left blank. Many stored labels cannot be read
  from the alert alone (time-window labels; synthetic rules used under both labels), so every accuracy figure here
  measures agreement with these labels, not with what an analyst would decide. A sensitivity analysis with the
  author's labels has not been run.
- **Held-out wording is a single set.** The detector result on wording c (4%) shows overfitting to a and b; it does
  not estimate how a real, adaptive attacker would fare.
- **Easier than reality.** Ambiguous alerts are excluded, and each alert is judged without surrounding events.
- **Split by rule.id.** This prevents near-copies in test, but few distinct rules decide the result.
- **Injection results apply only to the tested payloads and models.** Payloads are not adaptive, and the detector
  patterns were written alongside them. The held-out wording is "not tuned on", not independent.
- **Injection cases are clustered.** Several cases share one base alert, so exact intervals on ASR are too narrow;
  the tables also list base alerts. The harmless-text control has only two wordings and a different length than most payloads.
- **No authentication, no live integration.** Lab prototype only.
